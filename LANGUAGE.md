# English and Bangla

Use **বাংলা / English** in the navigation bar. Login, registration, verification and password-reset pages also have the switch. English is the default; the choice is saved under the `language` browser-storage key and synchronized between tabs. If storage is unavailable, switching still works for the current page. Switching uses React subscriptions and does not remount forms, reset typed values or reload the page.

Interface translations cover the public pages, sports labels, account forms, customer/owner/admin dashboards, schedules, reports, photo controls and common feedback. `frontend/src/i18n/bn.js` contains the English-to-Bangla catalog. `useTranslation()` exposes `t`, `n`, `locale` and `language`. Stable API enum values, roles, dates, numeric inputs, IDs and prices are never translated before submission. Owner-entered complex/field names, messages, reviews, email addresses and phone numbers remain as entered. This is frontend localization; existing emails and historical user content are retained in their original language.

Taka display uses the selected locale, dates and times use `bn-BD` or `en-BD`, and display counters support Bangla digits. HTML `lang`, page titles, descriptions and Open Graph locale track the preference. A self-hosted Noto Sans Bengali font supplies Bengali glyphs; only its Bengali subsets at weights 400/600/700 are imported. Shared authentication storage reads/writes are guarded so disabled storage does not crash the guest language switch.

Validation: the catalog audit found no missing literal translation keys. Chromium and WebKit checks at 320px, 390px, 1024px and 1440px covered switching, reload persistence, translated navigation and preserved typed form values without overflow or browser errors. Mocked owner checks verified Bangla dates/prices/statuses while generation and pricing payloads retained canonical values. Mocked admin checks verified all major tabs and unmodified customer messages; registration preserved names, emails, passwords and role IDs. Disabled-storage/light-theme checks passed. Existing English owner schedule, contact prefill and admin deletion workflows also passed. No real registrations, bookings or emails were created by these checks. Build and lint passed; existing lint warnings remain.

Deploy the built frontend with `scripts/update-hostinger-frontend.ps1`. It preserves the backend, database and environment, keeps old hashed assets for existing sessions, normalizes public build permissions and checks that the entry URL returns JavaScript. Verify rendered pages and the language switch after activation.
