# Featured homepage placements

Implemented locally on 2 November 2026. This feature requires the coordinated backend migration and frontend release; it has not yet been activated on Hostinger.

Owners open **Feature your complex** from the main field schedule or complex-management page. The packages are fixed server-side: **15 days / ৳150**, **30 days / ৳300**, **60 days / ৳500**. A complex must be approved, active, have an active owner and at least one field. No payment number is invented or seeded: a superadmin must configure SportEvo's receiving accounts first.

An owner chooses a package and available bKash, Nagad or Card receiving method, creates a request, pays externally using its displayed receiving number, then submits a transaction ID/reference. This is manual payment verification, not a payment gateway. Package amount, duration, method and encrypted receiving-number snapshot are set by the server. Later receiving-account changes do not alter existing requests. References are encrypted at rest and visible only to that owner and authorized platform staff.

Both admins and superadmins use **Featured complexes** in the platform dashboard. Its notification count includes open requests. They confirm actual receipt and approve a submitted request, or confirm directly without a reference after checking payment themselves. The approval endpoint requires explicit receipt verification. Approval starts the paid period at the time of approval; renewals extend the existing expiry so remaining time is preserved. Repeated approval cannot extend time twice. Rejection requires a note; any payment already received must be resolved with the owner externally.

Both staff roles can also add an approved complex directly without claiming payment, edit placement dates/order, or remove it at any time. These actions require an admin note and are audited. Removing a placement disables its listing; it does not delete the complex, fields, bookings, invoices, payment history or ledger. Editing a listing never rewrites an approved payment's quoted amount or original period. Lower display-order numbers appear first; admin date inputs explicitly use Bangladesh time.

**Only superadmins** can read/edit the receiving-account settings endpoint or see its editor. Ordinary admins cannot change SportEvo's bKash/Nagad/Card numbers by calling the API. They can view the historical receiving number on payment requests they review. Settings are encrypted; audit entries contain provider names, not account numbers or references. Owners may see currently enabled receiving methods for checkout. Public homepage responses exclude payment and owner-contact data.

The homepage section displays up to nine active featured complexes in three desktop columns/rows, with one column on small phones. Paid listings are labeled Sponsored; manual staff placements are labeled Featured. Without active featured placements it retains a normal selection of up to nine approved complexes. Name/sport searches continue to search the whole directory, and Browse all complexes remains available. Expired, disabled, archived, unapproved and deleted-owner placements are excluded by the live query, without depending on a cron job. Open homepages refresh the section each minute.

To avoid accepting payments for more than nine places, capacity includes distinct eligible complexes with an active placement **or an open payment request**, under a shared database row lock. An unpaid request can be cancelled by its owner; a request with a submitted reference requires staff resolution. Admin rejection/cancellation releases the reservation. One open request per complex is allowed. Staff can add the same reserved complex, but cannot overbook another place. Renewals reuse that complex's place.

Data lives in `featured_settings`, `featured_requests` and `featured_placements`, added by `2026_11_02_000002_add_featured_complex_placements.php`. Rollback refuses to discard configured receiving settings or request/placement history. This revenue is separate from booking commissions and never creates a booking wallet charge.

Public endpoint: `GET /api/featured-complexes`. Owner endpoints: `GET /api/featured/owner`, `POST /api/featured/requests`, and per-request `/reference` or `/cancel`. Staff endpoints: `/api/admin/featured`, per-request `/approve` or `/reject`, and placement create/update/delete. `/api/admin/featured/payment-settings` is superadmin-only. Authenticated payment responses use private/no-store caching.

Use `scripts/update-hostinger-maps-auth.ps1 -PrepareOnly` to build the full coordinated package, then `-UsePrepared` in an interactive SSH window when deployment is requested. The helper applies this additive migration, preserves private environment/old records and public assets, and verifies the new public endpoint before marking success. Publishing only frontend assets to an older backend will fail.
