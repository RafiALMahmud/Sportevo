# Booking guide, shorter deadlines and mobile editing

Implemented locally on 2 November 2026; pending Hostinger deployment with the featured-complex release.

**How to book** is available to visitors immediately through the desktop navbar and phone menu, linking to public `/how-to-book`. The interactive guide also appears expanded in the customer dashboard and can be opened in My Bookings. Users can choose any of four steps or move with Previous/Next. English/Bangla switching is available inside the guide and uses the site's existing language preference. Light/dark styles and keyboard controls are supported. The public guide is included in the sitemap.

The steps explain: request a slot without paying first; wait for owner acceptance; pay the advance to the account shown in My Bookings and submit a transaction ID/reference before the displayed deadline; wait for owner receipt confirmation. They distinguish submitted references from final confirmation, explain that timely references keep the slot reserved during review, and explain expiry/release and the advance-disabled/waived path. Homepage booking instructions were corrected to describe the same workflow.

The minimum configurable booking advance window is now **10 minutes**, with the existing **60-minute default** and **10,080-minute maximum**. Validation and both registration/settings inputs agree. The timer starts at owner/admin acceptance; saved booking terms remain snapshots and later setting changes do not rewrite existing bookings. Tests cover rejection below ten minutes, accepting ten minutes and expiry based on acceptance rather than the original request time.

Below **900 CSS pixels**, selecting a slot in the owner's schedule opens the existing controls in a native modal dialog rather than scrolling to a separate panel. It contains the same price, availability, offline booking, advance and request actions. The dialog traps focus, blocks background scrolling, supports Close/Escape/backdrop dismissal when no action is saving, and returns focus to the selected slot in Safari as well as Chromium. Save/delete actions close it using the existing selection reset. Desktop retains the side panel. Multi-select deletion stays on the slot grid and never opens the popup; booked-slot deletion restrictions are unchanged.

Validation includes 195 backend tests / 1,811 assertions, a production build and lint with existing warnings. Chromium/WebKit phone/desktop fixtures cover featured requests and references, admin approvals/edit/removal, superadmin-only settings, nine homepage cards, mobile/desktop slot editing and protected booked slots, bilingual guide controls and navigation. Tests use intercepted write APIs and an isolated SQLite test database; no real account, booking, payment or email is created by them.
